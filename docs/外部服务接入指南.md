# 外部服务接入指南

> 适用版本：v1.0.3+
> 设计原则：**零第三方依赖 + Mock 优先**。四类外部服务全部用 Node 内置模块（crypto / net / tls）与全局 `fetch` 自行实现，不引入任何 SDK；**未配置密钥时自动降级为 Mock**（写日志到 `backend/logs/`），业务流程不受影响、不会抛异常中断。

## 一、总览

| 服务 | 实现文件 | Provider 切换 | Mock 日志 |
|------|----------|----------------|-----------|
| 短信（阿里云 / 腾讯云） | `backend/src/services/sms-service.ts` | `SMS_PROVIDER=mock\|aliyun\|tencent` | `logs/sms.jsonl` |
| 电子签章（e签宝 v3） | `backend/src/services/e-signature.ts` | `ESIGN_PROVIDER=mock\|esign` | `logs/e-signature.jsonl` |
| 邮件（SMTP） | `backend/src/services/mailer.ts` | 由是否配置 `SMTP_HOST` 等自动判定 | `logs/notifications.jsonl` |
| 微信模板消息 | `backend/src/services/wechat-provider.ts` | 由是否配置 `WECHAT_APP_ID` 等自动判定 | `logs/notifications.jsonl` |

所有服务都导出 `isXxxConfigured()` 供上层判断是否已启用真实通道。配置项集中在 `.env`（样例见 `.env.example`）。

## 二、短信

### 阿里云（V1 签名，HMAC-SHA1）

```ini
SMS_PROVIDER=aliyun
SMS_ACCESS_KEY_ID=你的AccessKeyId
SMS_ACCESS_KEY_SECRET=你的AccessKeySecret
SMS_SIGN_NAME=短信签名
SMS_TEMPLATE_DUNNING=SMS_123456789   # 催缴模板
SMS_TEMPLATE_BILL=SMS_987654321      # 账单通知模板
```

实现要点：按字典序拼规范化查询串 → `GET&%2F&<encoded query>` 作为 StringToSign → `HMAC-SHA1(AccessKeySecret + "&")` → Base64；百分号编码遵循 RFC 3986（`+`→`%20`、`*`→`%2A`、`%7E`→`~`）。请求走 `https://dysmsapi.aliyuncs.com/`，响应 `Code === 'OK'` 视为成功，`RequestId` 落盘便于对账。

### 腾讯云（TC3-HMAC-SHA256）

```ini
SMS_PROVIDER=tencent
SMS_ACCESS_KEY_ID=SecretId
SMS_ACCESS_KEY_SECRET=SecretKey
SMS_APP_ID=1400000000        # 短信应用 SdkAppId（必填）
SMS_SIGN_NAME=短信签名
SMS_REGION=ap-guangzhou      # 可选
```

实现要点：规范请求串 → 待签串 → 四级派生密钥（`TC3+SecretKey` → date → service → `tc3_request`）→ HMAC-SHA256 十六进制签名，随 `Authorization` 头发送；手机号自动补 `+86`；模板参数按键名排序转为有序数组（与模板占位符顺序对应）。

### 通用行为

- 超时：`SMS_TIMEOUT_MS`（默认 10s），超时/网络异常写日志并返回 `false`，**不会中断催缴定时任务**。
- 每次发送（成功或失败）都追加一行 `logs/sms.jsonl`，含 provider、模板、参数、错误原因、requestId。

## 三、电子签章（e签宝 v3）

```ini
ESIGN_PROVIDER=esign
ESIGN_APP_ID=你的AppId
ESIGN_APP_SECRET=你的Secret
ESIGN_SERVER_URL=https://openapi.esign.cn   # 沙箱：https://smlopenapi.esign.cn
ESIGN_FILE_ID=默认待签署文件ID              # 也可写入合同 billingConfig.esignFileId
ESIGN_NOTIFY_URL=https://你的域名/api/callbacks/esign   # 可选
```

调用链：`POST /v3/oauth2/token`（token 内存缓存，提前 5 分钟过期，并发去重）→ `POST /v3/sign-flow/create-by-file`（发起流程）→ `POST /v3/sign-flow/{id}/sign-url`（取 H5 签署链接）→ `GET /v3/sign-flow/{id}/detail`（查询状态）。

状态映射：`2`→已签署、`3/4`→已撤销或拒签、`5`→已过期、其余→待签署。token 失效（41001/41003/401）自动清缓存。

## 四、邮件（内置 SMTP 客户端）

```ini
SMTP_HOST=smtp.example.com      # 必填
SMTP_USER=账号                   # 必填
SMTP_PASS=密码或授权码           # 必填
SMTP_PORT=465                   # 465=隐式 TLS（默认）；587/25=明文 + STARTTLS
SMTP_FROM=物业租赁管理系统 <noreply@example.com>   # 省略时取 SMTP_USER
SMTP_SECURE=true                # 可选，不填按端口推断
SMTP_TIMEOUT=15000              # 可选，单次读响应超时（毫秒）
SMTP_TLS_INSECURE=false         # 可选，自签名证书内网服务器设 true
```

实现要点（`backend/src/services/mailer.ts`）：

- `node:tls` / `node:net` 手写 SMTP 会话：问候 → EHLO（失败回退 HELO）→ STARTTLS（仅当 EHLO 响应含 STARTTLS 时升级并重新 EHLO）→ AUTH LOGIN（334/334/235）→ MAIL FROM → RCPT TO → DATA(354) → 报文 + `<CRLF>.<CRLF>` → QUIT。
- 按行缓冲解析多行响应（`250-` 续行累积、`250 ` 结束行派发），非 2xx/3xx 抛出**带服务器原始多行文本**的错误。
- 中文主题按码点切分做 RFC 2047 `=?UTF-8?B?...?=` 编码（每个编码字 <75 字符，超长折行）；正文 `text/html; charset=UTF-8` + base64（76 字符折行）；DATA 段行首点号填充。
- 每次读响应都有超时保护，异常时销毁 socket；未配置或发送失败均返回 `{ success:false, error }`，**从不抛异常**。

## 五、微信公众号模板消息

```ini
WECHAT_APP_ID=公众号AppID
WECHAT_APP_SECRET=公众号AppSecret
WECHAT_TEMPLATE_ID=模板消息ID     # 模板需含 first / keyword1 / remark 三个占位字段
WECHAT_API_TIMEOUT=10000         # 可选
WECHAT_API_BASE=                 # 可选，仅联调用（默认官方域名）
```

实现要点（`backend/src/services/wechat-provider.ts`）：`cgi-bin/token` 获取 access_token，按 `expires_in` 提前 5 分钟过期缓存（缓存绑定 appId，配置变更自动失效），并发调用复用同一 in-flight Promise 避免限流；`message/template/send` 下发模板消息；`errcode` ∈ {40001, 42001, 40014} 时清缓存、强制刷新并**自动重试一次**。

调用方式：`sendNotification({ channel: '微信', openid, title, content, ... })` —— `openid` 为可选入参（**未改动任何数据库模型**）；需要自定义模板字段时直接用 `sendTemplateRaw(openid, data, url?)`。

## 六、自检与验证

不需要真实账号即可验证签名算法与降级行为：

```bash
cd backend && npx tsx ../scripts/verify-external-providers.ts
# 21 项：百分号编码规则、阿里云签名确定性/参数无序性、TC3 结构与派生链、未配置时的降级
```

该脚本校验的是**算法结构与自洽性**（编码规则合规、相同输入必得相同签名、签名随密钥/参数/日期/服务变化），以及"未配置密钥时不抛异常、Mock 可用"的降级契约。真实链路仍需在拿到账号后用服务商控制台验证一次。
