## 项目背景

<!-- cards:3 | 行业痛点=传统物业管理普遍采用纸质台账或Excel管理，数据分散、查询困难、容易出错 | 政策驱动=金税四期上线对财务规范化提出更高要求，租赁合同电子化成为趋势 | 技术机遇=Electron跨平台桌面技术成熟，Vue3/Express等开源框架生态完善 -->

### 行业痛点

- **信息化水平低**：大量中小物业公司仍用纸质台账或Excel管理，缺乏统一的信息系统
- **业财分离严重**：租赁运营与财务管理割裂，收租数据需重复录入财务软件
- **合同管理混乱**：合同条款不统一、审批流程不规范、到期续约无提醒机制
- **催缴效率低下**：依赖人工电话/贴条催缴，逾期管理被动、回款周期长

### 解决方案

本项目为**桌面端一体化物业租赁管理系统**，将收租管理、财务报表、合同管理三大核心业务整合在一个应用中，通过 Electron 打包为 Windows 桌面安装包，开箱即用。

<!-- kpi: 服务规模=50~500套房源[#0A3D62] | 支持业态=3种[#F6B93B] | 管理角色=9个[#00B894] | 数据模型=30个[#82CCDD] -->

## 系统定位

<!-- cards:3 | 非SaaS模式=单机部署，数据本地存储，无需互联网连接，保障数据隐私和安全性 | 多业态覆盖=支持公寓、厂房、商铺三种物业业态，一套系统满足混合业态管理需求 | 业财一体化=将租赁运营与会计核算无缝衔接，收租自动生成记账凭证，消除信息孤岛 -->

### 适用范围

| 维度 | 分类 | 说明 |
|------|------|------|
| 物业规模 | 小型（50-100套） | 单机SQLite即开即用 |
| 物业规模 | 中型（100-300套） | 支持切换到MySQL |
| 物业规模 | 大型（300-500套） | MySQL + Redis 缓存加速 |
| 物业业态 | 公寓 | 标准住宅，按套/间管理 |
| 物业业态 | 厂房 | 工业生产，按栋/层管理 |
| 物业业态 | 商铺 | 商业经营，按铺位管理 |

## 核心价值

<!-- cards:3 | 收租管理高效化=自动账单生成+多渠道收款记录+智能四级催缴+数据看板实时监控 | 财务管理规范化=标准26科目体系+双分录凭证+税务计算+三大主表自动生成 | 合同管理数字化=全生命周期闭环+模板标准化+合规检查+到期自动提醒 -->

## 系统特色

- **三位一体**：运营管理 + 财务核算 + 合同管理在同一平台，数据互通无孤岛
- **数据实时互通**：合同签订自动关联房源状态，收租到账自动生成记账凭证
- **业财一体化**：租金收入、水电费用、物业费用直接归集到会计科目，无需手工对账
- **多业态支持**：公寓/厂房/商铺共用一套系统，切换业态类型即可适配
- **高性能体验**：SQLite本地数据库毫秒级响应，前后端分离架构流畅不卡顿
- **数据安全保障**：JWT双Token认证+RBAC九角色权限+审计日志全链路追踪
- **弹性扩展能力**：默认SQLite零配置，业务增长可平滑切换到MySQL+Redis

## 模块概述

<!-- kpi: 房源状态=9种[#0A3D62] | 智能锁管理=2大品类[#F6B93B] | 打印模板=5套[#00B894] | WebSocket事件=8类[#82CCDD] -->

租赁管理模块涵盖房源、租客、收租、催缴、门锁、打印、房态看板七大子模块，是系统的核心业务引擎。

<!-- flow: 房源登记 → 租客签约 → 账单生成 → 收款记账 → 催缴跟进 -->

## 房源管理

### 核心功能

- **多业态支持**：公寓/厂房/商铺三种业态，每种业态可自定义子类型
- **楼栋房号体系**：buildingName + roomNumber 双字段，支持楼栋楼层的层级化管理
- **9种状态流转**：空置→已锁定→已预订→已出租→退租中→待保洁→待验收→维修中→已冻结，严格状态机规则控制
- **批量导入**：Excel 批量导入房源，自动解析楼栋楼层信息
- **状态变更审计**：每次状态变更均记录 RoomStatusLog（操作人/时间/原状态/新状态/关联合同），仅追加不可修改

### 房态看板

<!-- cards:3 | 主看板=楼栋/楼层筛选+网格卡片+表格视图切换+快捷操作抽屉+批量状态变更 | 数据大屏=暗色主题+ECharts可视化（玫瑰饼图/柱图/仪表盘/热力图/趋势线/桑基图+告警跑马灯） | 批量生成=按楼栋+楼层范围+每层房间数+命名规则自动生成房间 -->

房态变更通过 WebSocket 实时广播（`room:status-changed` / `room:batch-status-changed`），看板前端自动刷新无需手动F5。

## 租客管理

### 核心功能

- **租客档案**：基本信息、证件信息（支持身份证/营业执照/护照）、联系方式
- **身份证读卡器集成**：Provider 模式架构，支持华视/新中新/普天/精伦/中控等品牌，身份证号 ISO 7064:1983 MOD 11-2 校验
- **信用评分**：基于缴费及时性、合同履约、物业配合度三维度计算，输出 A/B/C/D 四个信用等级
- **租客关联**：一个租客可关联多个合同，详细记录入住/退租/续约历史

## 智能催缴

### 四级催缴引擎

<!-- flow: 到期前提醒(Level 1) → 逾期1-7天(Level 2) → 逾期8-30天(Level 3) → 逾期30天+(Level 4) -->

不同等级的催缴策略可独立配置（通知渠道、模板内容、发送时段），当前以 Mock 模式运行（写日志），接入阿里云/腾讯云 SMS 即可真实发送。

## 门锁管理

### 双品类架构

| 品类 | 管理对象 | 核心操作 | 关键字段 |
|------|---------|---------|---------|
| 智能门锁 | DoorLockPassword | 远程开锁、生成临时密码、设置密码有效期和次数限制 | 密码/有效期/次数上限/已使用次数 |
| 传统门锁 | DoorLockKey | 钥匙借出/归还、挂失登记、作废流转 | 钥匙编号/借用人/借出日期/归还日期/状态 |

## 打印功能

<!-- cards:5 | 租赁合同=法律标准格式+双方签章位+公司Logo，A4竖版 | 租客信息=租客信息表+关联合同列表，A4竖版 | 账单明细=费用分项表+金额大写，A4竖版 | 收款收据=80mm热敏小票格式 | 批量汇总=合同批量汇总表，A4横版 -->

<!-- section: 03 | 财务报表 | Financial Reporting Module -->

## 模块概述

<!-- kpi: 会计科目=26个[#0A3D62] | 财务报表=3大类[#F6B93B] | 税务税种=5种[#00B894] | 定时折旧=月度[#82CCDD] -->

财务管理模块涵盖账套、会计科目、记账凭证、费用核算、税务管理、预算管理、报表中心、财务看板八大子模块。

## 账套管理

支持**多账套并行**，每个账套独立核算。默认创建"默认主账套"，可根据管理需要创建多个分账套（按项目/业态/区域拆分）。

## 会计科目

内置**26个标准会计科目**（4级科目体系），涵盖资产类、负债类、权益类、收入类、费用类。支持科目树的父子层级展示和自定义扩展。

### 科目体系

| 类别 | 科目数量 | 示例科目 |
|------|---------|---------|
| 资产类 | 8个 | 现金/银行存款/应收账款/固定资产/累计折旧 |
| 负债类 | 5个 | 应付账款/预收租金/应交税费/其他应付款 |
| 权益类 | 3个 | 实收资本/未分配利润/本年利润 |
| 收入类 | 5个 | 租金收入/物业费收入/水电费收入/其他收入 |
| 费用类 | 5个 | 维修费/保洁费/安保费/办公费/折旧费 |

## 凭证管理

### 工作流

<!-- flow: 草稿 → 待复核 → 待审核 → 已过账 -->

- **自动生成**：收租到账时自动生成记账凭证（借：银行存款 / 贷：租金收入等）
- **手动录入**：支持双分录表单，科目选择器（el-tree-select），借贷金额自动平衡校验
- **审核流程**：草稿→待复核→待审核→已过账，四级审核确保凭证质量

## 费用核算

支持 **维修/保洁/安保/绿化/办公/折旧/其他** 七类费用分类管理。每笔费用关联账套和科目，审批通过后自动生成凭证。

## 税务管理

| 税种 | 计税方式 | 申报周期 |
|------|---------|---------|
| 增值税 | 一般纳税人/小规模纳税人 | 月/季 |
| 房产税 | 从价计征/从租计征 | 月/季/年 |
| 城镇土地使用税 | 按面积×适用税额 | 年 |
| 印花税 | 按合同金额×税率 | 次 |
| 企业所得税 | 按应纳税所得额×25% | 季/年 |

## 预算管理

预算编制→审批→执行→监控，支持预算科目维度的支出控制和超预算预警提醒。

## 报表中心

- **三大主表**：资产负债表、利润表、现金流量表
- **管理报表**：收入明细表、费用分析表、账龄分析表、催缴统计表
- **自定义报表**：灵活选择期间范围、科目范围、对比维度

## 财务看板

<!-- kpi: 总收入[#00B894] | 总支出[#FF6B35] | 净利润[#0A3D62] | 利润率[#F6B93B] -->

实时展示关键财务指标（收入/支出/净利润/利润率/税负率），配合ECharts趋势图、收入构成饼图、费用分类柱状图。

## 模块概述

<!-- kpi: 合同状态=8种[#0A3D62] | 审批效率提升=300%[#00B894] | 纠纷降低=80%[#00B894] | 到期提醒=7/30/90/180/365天[#F6B93B] -->

合同管理模块涵盖全生命周期管理，从起草到归档八个阶段形成完整闭环。

<!-- flow: 起草 → 提交审批 → 审批通过 → 签订执行 → 到期提醒 → 续约评估 -->

## 合同全生命周期

| 阶段 | 操作 | 状态标记 |
|------|------|---------|
| 1. 起草 | 选择模板→填写信息→配置费用→上传附件 | 草稿 |
| 2. 提交 | 提交审批→通知审批人 | 待审批 |
| 3. 审批 | 多级审批→意见记录→驳回/通过 | 审批中/已驳回 |
| 4. 签订 | 电子签章→线下用印→双方签章 | 已签订 |
| 5. 执行 | 关联房源→生成账单→跟踪履约 | 执行中 |
| 6. 变更 | 条款变更→补充协议→变更记录 | 变更中 |
| 7. 到期 | 多级提前提醒→续约评估→决定续约/终止 | 即将到期 |
| 8. 归档 | 合同归档→历史查询→档案管理 | 已到期/已终止 |

## 合同起草

- **模板选择**：从模板库中选择标准合同模板，自动填充条款
- **费用配置（billingConfig）**：可扩展 JSON 字段，支持配置租金/水费/电费/物业费分项、收款方式、银行账号、税务细则（含税类型/税率/发票类型）、违约金率、押金条款、维修责任方、解约通知期限、续约通知期限、转租许可等
- **房源租客关联**：选择房源和租客，自动带入相关数据

## 合同审批

多级审批流程（主管→法务→财务→总经理），每级可录入审批意见。审批超时自动升级提醒。审批记录永久可追溯。

## 履行与变更

- **履行跟踪**：合同执行中自动关联房源状态、账单生成
- **变更管理**：合同条款变更需走补充协议流程，完整记录 ContractChange
- **合同看板**：八列看板（Kanban）按状态分组，拖拽式卡片管理

## 续约与到期管理

<!-- cards:3 | 多周期提醒=到期前7天/30天/90天/180天/365天多级预警，自动标记到期状态 | 一键续约=选择目标合同→修改续约条款→一键生成新合同，原合同自动关联续约记录 | 到期日历=月度日历视图，每日标注到期合同数量和金额 -->

## 法务合规

- **条款库管理**：标准法律条款模板，确保合同条款合法合规
- **合规检查**：自动检查合同必备条款完整性、租金合理性、押金合规性
- **风险预警**：对异常条款（过高违约金、不合理免责条款）自动标红提醒
- **电子签章**：预留 e签宝/法大大 SDK 接口，当前 Mock 运行

## 合同模板

支持创建和管理多种合同模板，每种模板关联标准条款库。模板按业态类型分类（公寓/厂房/商铺）。

9种角色 × 6种操作（create/read/update/delete/approve/export），路由级粗粒度隔离 + 操作级细粒度控制。

## 数据库设计

| 类别 | 模型数 | 代表性模型 |
|------|--------|-----------|
| 核心业务 | 12个 | Property / Tenant / Contract / Bill / PaymentRecord / DunningTask / DoorLock / DoorLockPassword / DoorLockKey / DoorLockLog / RoomStatusLog / IdCardReader |
| 财务模块 | 7个 | AccountBook / ChartOfAccount / Voucher / VoucherEntry / Expense / Budget / TaxRecord |
| 合同相关 | 4个 | ContractTemplate / ContractClause / ContractChange / ContractLog |
| 系统管理 | 7个 | User / AuditLog / Approval / Notification / SystemConfig / DictType / DictItem |

总计 **30个数据模型**，支持 SQLite（零配置）和 MySQL（大规模）双数据库引擎。自带轻量级迁移系统解决 SQLite 不支持 ALTER TABLE 的局限。

## WebSocket 实时通信

| 事件 | 触发时机 | 广播数据 |
|------|---------|---------|
| `room:status-changed` | 单个房态变更 | propertyId / oldStatus / newStatus / operator |
| `room:batch-status-changed` | 批量房态变更 | affectedIds / newStatus / count |
| `contract:created` | 合同创建 | contractId / contractNo / propertyName |
| `contract:deleted` | 合同删除 | contractId / contractNo |
| `contract:renewed` | 合同续约 | oldContractId / newContractId |
| `contract:status-changed` | 合同状态变更 | contractId / oldStatus / newStatus |
| `id-card:read-success` | 身份证读卡成功 | readerId / tenantId(如有) |
| `id-card:read-failure` | 身份证读卡失败 | readerId / error message |

前端通过 `useWebSocket()` composable 订阅事件，自动重连（3秒间隔），生产模式自动回退到 `ws://localhost:3001/ws`。
